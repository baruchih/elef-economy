# Independent review — Agentic Economics v0.7

## Verdict and scope

**The v0.6 boundary findings are repaired in the supplied v0.7 package.** All three supplied test entry points report 104 passing runs and one expected failure, and the previous independent boundary file is present byte-for-byte unchanged. This is substantive conformance progress.

The additional review found **seven failing checks in five issue groups**, plus six passing checks. Some are clear implementation defects; two areas need an explicit interpretation of the existing rules as well as an implementation repair. One failure deliberately supplies an incorrectly typed appeal explanation and is lower-priority boundary hardening, not a claim about a valid-text strategy. Separately, the rotation rule permits same-tick re-entry; that observation is not counted as a conformance failure.

The review uses the attached v0.7 specification, its inherited v0.6–v0.1 clauses, and the code extracted from **agentic_sim_v0_7.zip**. It does not use the old loose `engine.py` or `ledger.py`. No supplied source or test file was edited. The scope is the deterministic protocol harness, not an implemented economic policy, learned selector, evaluator, external history anchor, or real reserve exchange.

## A. A requester dispute after a human ruling still targets the overruled verdict

**Rule basis:** v0.7 §8.3/15.2 prohibits audits after a human ruling. It does not explicitly prohibit requester disputes after that ruling. Inherited §8.2 permits a requester dispute of pending F inside the window. Whichever rule is intended, an admitted flow must settle or be refused atomically.

**Reproduction:**

1. A submits; C returns N.
2. H overrides to F. C's rejection is overturned and its bond forfeited.
3. While F is pending and the challenge round is unused, H calls `dispute(...)`.
4. The engine accepts the filing and its court fee, then assigns D and E.
5. D and E both return F.

**Observed:**

- D's view says `question='dispute'` but `appealed_assessment='N'`, even though the pending result being disputed is F.
- Completion of E's review raises `RuleError: no completed initial review`.
- The challenge is already marked resolved, both new reviews are done, but `open_items` remains 1.
- The case remains PENDING, with A's guarantee and the new reviewers' bonds locked.
- All 18 invariant checks pass in that stranded state.

**Cause:** `dispute()` admits using `outcome_or_verdict()`, while `observe()`, the challenge commitment, and `_settle_challenge()` use the old `c.verdict`. Settlement attempts to overturn C again through `_initial_review()`, which only returns a review still marked done; C is already overturned.

**Source locations:** `sim/engine.py:466–478`, `678–725`, `788–820`, especially `793–801`; `_initial_review()` at `670–675`.

**Correction boundary:** Decide whether a requester may open a new dispute after a human ruling. If not, reject it before collection and mutation. If yes, use the specifically challenged live assessment and its actual financial responsibility; do not reapply a penalty to a superseded original review. The regression explicitly accepts either a whole refusal or coherent completion, rather than silently choosing the policy.

**Test:** `test_requester_dispute_after_ruling_is_refused_whole_or_settles`.

## B. Human overrides of delegate-requested cases conflict with grade provenance

**Rule basis:** v0.4 §15.3 distinguishes human-explicit and delegate-explicit judgments; v0.5 §15.2 calls a human override before vesting a ruling and a root's grade human-explicit. The source also describes delegate grading by root-requester identity. The case in which a real human overrides a delegate-originated request needs a single interpretation.

**Reproduction:** S is a delegated requester and H is an actual human. S funds the root request. The engine accepts an override from H.

| H's override route | Result | Check |
|---|---|---|
| N to F, before vesting | Case vests as `delegate-explicit` | Passes |
| F to N, before vesting | Case ends as `human-explicit` | I13 fails: requester is a delegate |
| F to N, after vesting | No money moves; case changes to `human-explicit` | Same I13 failure |

The first route is a **passing characterization**, not an assertion that its grade is the chosen answer. The additional tests permit either grade policy if the admitted transition and invariant agree. They also permit an atomic authority refusal if that is the selected rule.

**Cause:** `_grade()` chooses the grade from `c.requester in self.delegates`. The N and post-settlement branches in `override()` write HUMAN directly. I13 uses requester identity again. The override author's role and request owner's role have been conflated differently on different paths.

**Source locations:** `sim/engine.py:934–1010`, especially `959–973`, `983–987`, `1001–1004`; `_grade()` at `1032–1041`; `sim/invariants.py:162–193`.

**Correction boundary:** Clarify which accepted event establishes the grade when the requester and adjudicating human have different roles, and apply the same definition during settlement and invariant checking. If H is not authorized for that request, refusal must precede all consequences. No new monetary mechanism is required.

**Tests:** `test_actual_human_override_of_delegate_request_is_consistent[before_N]` and `[after_N]`; `[before_F]` passes as described.

## C. Execution-cost attribution is not constrained by the case commitment

### C1. Another actor's purchase increases the contractor's kill fee

**Rule basis:** v0.5 §4.6 defines the contractor's execution cost in credits; §9.3 reimburses the subcontractor's cost to date on cancellation, including its own nested payments and kill fees. No selected rule converts an unrelated actor's own purchase into the contractor's incurred expense.

**Reproduction:**

1. A hires B for a five-credit child task.
2. C executes `spend('C', 4, child)`.
3. A cancels the child before submission.

**Observed:** C spent four credits; B spent none. The engine nevertheless records `child.actor_cost == 4`, pays B a four-credit kill fee from A's escrow, and returns the remaining one credit to A. B gains four, C loses four, and all 18 invariants pass.

This is a permitted public-API call with valid participant and case identifiers; no balances or records were edited. It is not a claim that the unrelated expenditure was fraudulent by itself. The defect is its attribution as B's reimbursable expense.

**Cause:** `spend()` checks that the actor and case exist, but does not relate the actor to the commitment. Every credited cost is added to `c.actor_cost`. `cancel_nested()` trusts that aggregate.

**Source locations:** `sim/engine.py:392–400`, `851–879`.

**Correction boundary:** Refuse incompatible actor/case attribution before the purchase, or explicitly record a permitted third-party expenditure separately rather than billing it as the contractor's own cost. The test permits refusal or separate attribution. Inventing a donation/sponsorship mechanism is not required.

**Test:** `test_other_actor_cost_cannot_become_contractor_kill_fee`. A control confirms that B's actual own expenditure enters the kill-fee calculation correctly.

### C2. Post-vesting expenditure is admitted and then fails I10

**Reproduction:** Fulfill and vest a root request at tick 10. At tick 11 call `spend('A', w.ledger.v, q)`, consuming exactly one credit of resources.

**Observed:** The action succeeds and debits A by one credit. `check_all()` then raises `I10 ... purchase 1.0 at t=11 after vesting at 10`.

**Rule boundary:** Financial finality forbids new adjudication-driven movements, not all conceivable future purchases. The test does not decide whether this later expenditure should be allowed. It requires admission and the selected finality check to agree. If post-finality work belongs to a new request, reject the old-case attribution before expenditure; if the existing specification permits the event, distinguish it in I10 rather than admitting it into an invalid state.

**Source locations:** `sim/engine.py:392–400`; `sim/invariants.py:130–141`.

**Test:** `test_spend_on_vested_case_is_rejected_whole_or_invariant_consistent`.

## D. Malformed appeal grounds cause partial admission

**Classification:** Lower-priority input-validation hardening. The argument is deliberately not the annotated `Optional[str]` type. This is not evidence of a profitable policy or a failure of valid-text appeals.

**Rule basis:** v0.6 §2.2 requires full validation before any financial, state, or admissible-record change. v0.7 §14 now commits the challenge's actual grounds.

**Reproduction:** After N, call:

```python
w.respond(q, 'appeal', d={0: 'mixed', 'key': 'types'})
```

**Observed:** JSON serialization raises `TypeError: '<' not supported between instances of 'str' and 'int'`. Before that error, A has paid two credits, the challenge round is used, `open_items` is one, and the challenge object exists. The case is still AWAITING_RESPONSE and there is no committed challenge entry. All 18 invariant checks pass.

**Cause:** `_open_challenge()` collects the fee and changes the round/challenge state before `History.append()` attempts serialization. `d` is not checked to be text. Merely annotating a Python argument does not validate the value at this boundary.

**Source locations:** `sim/engine.py:639–653`, `678–696`; `sim/ledger.py:86–93`.

**Correction boundary:** Check the payload's allowed type and serializability before state changes. The chosen textual schema is sufficient; no broader schema is proposed here. Valid text is exercised by the passing ordinary dispute control and existing appeal suites.

**Test:** `test_non_text_grounds_cannot_partially_admit_an_appeal`.

## E. A post-settlement BOT correction omits the original reviewer

**Rule basis:** v0.5 §8.1 defines separate objection disposition and fulfillment answers. Its §15.2 and v0.6 §15.2 preserve no clawback while adjusting reliability of contradicted assessments; a BOT is contradicted by a rejected objection rather than by an F/N comparison alone.

**Reproduction:**

1. C returns BOT, claiming needed evidence is missing.
2. A appeals; D and E answer `upheld, N`.
3. The case reaches final N and reviews settle.
4. H later overrides to `F, objection='rejected'`: the missing-evidence claim was not accepted.

**Observed:** Money correctly does not move. D and E's reliability each falls from 2/3 to 1/2. C's reliability remains 2/3, with its original BOT still counted only as a survival. All 18 invariants pass.

**Cause:** The post-settlement override branch only checks `r.verdict in (F, N)`. It never applies the two-question contradiction rule to the original BOT. The general `_contradicts()` helper already represents the required distinction, but this branch bypasses it.

**Source locations:** `sim/engine.py:959–973`, `1012–1022`.

**Correction boundary:** Apply the accepted correction to the original missing-evidence assessment as well as the F/N appeal assessments, while preserving financial finality. This is a correction to reliability/learning data, not a request to claw back fees.

**Test:** `test_post_settlement_bot_correction_reaches_the_original_reviewer`. The neighboring F-to-N post-vesting correction passes and changes no balances.

## F. Policy observation: reserve rotation can immediately recruit an actor it just released

This is **not counted as a conformance failure**. The sequential implementation can be read as following the current written rotation rule literally. It matters because the earlier purpose of rotation was to let actors leave mandatory verification duty and have an opportunity to do ordinary work.

With full defaults, eight actors A, B, C, D, E, F, G, I; C–F on duty; all duty credit zero; and no tasks, processing tick 30 yields:

| Swap | Enters duty | Leaves duty |
|---|---|---|
| 1 | A | C |
| 2 | B | D |
| 3 | C | E |
| 4 | D | F |

C and D are free only between calls in the same rotation batch. They are selected again before awards can occur. G and I remain free. The reserve size stays four and every invariant passes.

**Source locations:** `sim/engine.py:1207–1226`; inherited v0.5 §13.

The open policy question is narrow: should a just-released duty actor be eligible to re-enter in the same batch? A batch-start eligibility snapshot or some minimum release opportunity would change the behavior, but neither is silently adopted by this review. It is acceptable to study the current rule as written, provided this behavior is not mistaken for voluntary specialization.

The deterministic reproduction is in `reproduce_findings.py`, not asserted as a rule to preserve in the conformance suite.

## Minor documentation inconsistency

`sim/strategies.py:27–30` still says the view cannot identify a BOT appeal and that a policy may return an answer the engine rejects. That comment predates the working `ReviewView.question` and `appealed_assessment` fields. The implementation and new specification have fixed this problem; the comment should no longer instruct a future policy author otherwise. This is documentation only, not an additional failed check.

## Review disposition

I would accept the narrower claim **“v0.7 repairs the previous review's reproduced cases”**. I would not yet give a general conformance sign-off for all admitted driver actions.

The next repairs are bounded: align a new challenge with the actual assessment it targets; make role provenance consistent; constrain execution-cost attribution; validate the newly committed payload before collecting its fee; and apply two-question corrections on the post-settlement path. The rotation observation is a separate policy choice, not a reason to reopen the whole design.

Nothing here demonstrates that the economic incentives fail. Conversely, these bookkeeping and state effects should not be interpreted as learned economic behavior in an unrestricted strategy run. A tightly scoped experiment can explicitly exclude unresolved paths, but its scope and exclusions need to remain visible.
