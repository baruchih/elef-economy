# Agentic Economics v0.9 — Conformance review

**Basis:** `agentic_economics_loop_spec_v0_9.md`, its inherited rules, and the implementation extracted from `agentic_sim_v0_9.zip`.

**Review scope:** Run the supplied suites; verify the previous independent tests are preserved; exercise the newly allowed reopening-audit paths against existing time, capacity, replacement, adjudication, and settlement rules. This is not an economic-strategy run or an evaluation of learned behavior.

## Executive assessment

v0.9 repairs the v0.8 review's reproduced cases. All three supplied entry points report **148 passed and one expected failure**. The previous independent review file is included byte-for-byte unchanged and passes.

The new rule permitting auditors to return partially fulfilled (P) or cannot assess (⊥) is also a state-machine expansion: an already approved, capacity-released task can now return to the actor for action. The provided new examples exercise several immediate, idle-actor paths successfully. Additional checks find failures when time advances, another commitment exists, the resumed auditor times out, the audit concerns a nested request, or a requester dispute is already underway.

The additional suite contains **25 targeted cases: 16 failed and 9 passed**, grouped into five findings. Parameterized failures are not distinct root causes, and these selected tests are not a random sample or a failure-rate estimate. In particular, this result does not mean the previous fixes failed or the economic idea has been disproved.

I would preserve the selected economic rules and the successful repairs. Two intersections need a policy clarification as well as coherent code: what capacity is used when an audit reopens a busy actor's task, and what happens when the reopening audit has already been merged into a paid requester dispute. The other findings concern applying existing rules consistently.

## A. A new assessment replaces timestamps that earlier valid actions depend on

### A1. A non-instant audit cannot return P or ⊥ without failing I6

Rule basis: v0.9 §8.3 permits the audit to answer all four fulfillment categories and reopen the actor's response. The standing commit-before-audit rule concerns the approval that authorized the audit, not a verdict created later by that audit.

Reproduction:

| Tick | Event |
|---:|---|
| 0 | C approves A's result. |
| 1 | D is assigned to audit that approval. |
| 2 | D returns P or ⊥ within its five-tick review deadline. |

`complete_review()` accepts the answer. `_audit_reopens()` then changes `c.t_verdict` from 0 to 2. I6 compares the audit's assignment time, 1, with this new time and raises:

```text
I6 q1: audit assigned at 1 before the verdict at 2
```

The audit was validly assigned after the actual initial approval. Its own later answer did not make that earlier assignment invalid.

Both F and N controls on the same elapsed-time sequence pass. The supplied new P/⊥ examples perform the relevant events at one tick, so they do not expose the timestamp collision.

### A2. The same collision occurs when the actor takes time to supply evidence

An audit returns ⊥ at tick 0. The actor chooses to supply evidence, advances to tick 1, resubmits, and the auditor returns F or N. The completion path again assigns the current time to `c.t_verdict`. I6 then raises:

```text
I6 q1: audit assigned at 0 before the verdict at 1
```

This is not a late submission or a review timeout.

### A3. A child audit can invalidate the parent's already legal submission

A accepts B's nested result at tick 0 and legally submits the parent at tick 0. An audit of the child is assigned and returns ⊥ at tick 1. The child now has `t_verdict=1`, so I7 raises:

```text
I7 q1 submitted at 0 before nested q2 reached its milestone
```

The parent did not submit early. The mutable field used to check that fact no longer identifies the milestone the parent relied upon.

**Code:** `sim/engine.py:625–650`; `sim/invariants.py:92–114`.

**Correction direction:** Preserve the identity/time of the initial milestone and the assessment being audited separately from the current assessment and its response window. The existing history chain remains intact; the defect is in the live fields the checks use. Removing I6/I7 would hide rather than resolve the ambiguity.

## B. A resumed auditor can time out but cannot be replaced

Rule basis: v0.5 §7.5 permits replacement of timed-out positions; v0.6 §7.5 makes a vacant audit an obligation until replacement, waiver, or valid takeover; v0.7 §6.1 makes resubmission stage independent of reviewer identity. v0.9 says the ordinary response paths apply to the reopening auditor.

Reproduction, for either P→revise or ⊥→supply evidence:

1. Initial approval at tick 0.
2. D's audit returns P or ⊥ at tick 0.
3. The actor chooses its response and resubmits at tick 0.
4. D does not complete the resumed review; advance to tick 6.

Observed state:

```text
case.state       = SUBMITTED
suspended_verdict= F
audit_vacated    = True
open_items      = 0
D's review      = withdrawn
```

E is eligible and has ample unlocked funds. Nevertheless:

```text
assign_audit(q, "E")   -> only an F verdict in PENDING may be audited
assign_initial(q, "E") -> initial review already assigned
```

The existing original approval blocks assigning a new initial reviewer; the reopened task's state blocks assigning a replacement auditor. This is not scarcity of reviewers.

Calling `waive_audit()` instead is admitted and decrements `open_items` from zero to **−1**. The case remains SUBMITTED. All eighteen existing invariants accept that state.

The ordinary audit-timeout control, without reopening, can be replaced and settles successfully.

**Code:** `sim/engine.py:508–552, 641–653, 1273–1297`.

**Correction direction:** Carry the current assessment position through response, resumed execution, withdrawal, and replacement. Distinguish the vacancy from the old approval's status. A waiver must reconcile the particular obligation it closes; a negative count cannot represent a valid number of outstanding items. Whether waiver should restore an approval or leave another assessment requirement is a policy choice, not something this review selects.

## C. Reopening appeals do not consistently identify the liable assessor or active path

### C1. Upholding an auditor's ⊥ yields four counted positions after finalization

Rule basis: v0.9 §8.3 and I8 explicitly say the suspended approval is off the path and every branch fits within `V_max=3`.

Reproduction:

- C approves.
- D audits and returns ⊥.
- A appeals.
- E and F both return `upheld, N`.

The engine accepts the result and makes the case FINAL_N. C's premature approval is overturned. The count nevertheless becomes four:

```text
I8 q1 holds 4 review positions > V_max
```

`_finalize_N()` clears the suspension flag; `_positions()` then counts the historical, now-overturned initial approval again. Advancing a tick attempts reviewer settlement and raises the invariant again.

This does **not** demonstrate a need for a larger reserve. It is a mismatch in the definition of path membership. Historical participants and active path positions are already distinct concepts in the specification.

### C2. An appeal against a nested auditor tries to charge the parent

Rule basis: v0.9 §8.3 says rejection of the missing-evidence objection overturns **the auditor**, and reimburses the actor from **the auditor's bond**. Under the inherited nested rule, the parent has released its rejection bond when it accepted the child.

Reproduction:

1. A hires B and accepts B's result. A's child rejection bond is released.
2. C audits the child and returns ⊥.
3. B pays its two-credit court fee to appeal.
4. D and E both reject C's missing-evidence claim, returning F (or N) for fulfillment.

The second review completion raises:

```text
LedgerError: A lock rej:q2 holds 0.0, cannot take 2.0
```

`_settle_challenge()` dispatches every nested case to `_overturn_requester_verdict()` instead of identifying the auditor whose assessment is actually under appeal.

After the failed completion:

- The new review is already marked done.
- The challenge is already marked resolved, with an outcome.
- Its outstanding-item count remains 1.
- B has not been reimbursed.
- C's reviewer bond remains locked and C is not overturned.
- A has incorrectly received an adverse reliability record.
- All eighteen invariants pass.

The error reproduces for both `rejected,F` and `rejected,N`. These outcomes must remain distinct: evidence being present does not imply fulfillment.

The corresponding root-case appeals succeed, and the ordinary appeal of an actual parent's rejection succeeds. Those controls identify the failing combination as **a nested audit being used as the current assessor**.

### C3. Abandoning a nested reopening omits the parent's premature-approval consequence

A accepts B's nested result. C returns ⊥ on audit. B accepts N rather than supplying evidence or appealing. B loses its guarantee as prescribed, but A's reliability does not change.

The equivalent root path penalizes the initial approving reviewer. `_finalize_N()` only looks for a paid review with `role == "initial"`; there is no such review object for the nested requester-actor.

This finding concerns the reliability consequence of the parent's premature acceptance, not a proposal to reintroduce a second financial bond for nested acceptance. If the new rule intentionally excludes requester-actors from that consequence, that exception should be stated explicitly; it is not expressed in the general reopening rule.

**Code:** `sim/engine.py:464–478, 727–734, 851–911, 975–980`.

**Correction direction:** The case must retain who authored the assessment currently being challenged, independently of whether the task is root or nested. Settlement and finalization should use that target, and path membership should not revert to a historical count when a suspension ends.

## D. Reopening does not resolve which execution capacity the actor uses

Rule basis: a pending task releases capacity; an actor may accept other work or enter the rotating review reserve. One active assignment is still the standing rule. v0.9 adds a later mandatory response to an auditor.

### D1. Two ordinary tasks execute under one actor

At tick 0:

1. C approves A's task q1, releasing A.
2. A legitimately receives another task q2.
3. D audits q1 and returns ⊥.
4. A supplies evidence and resubmits q1.
5. A spends one real resource unit on q1 and another on q2.

All calls are admitted. q1 is SUBMITTED and q2 is COMMITTED, both attributed to A. A's `committed` pointer still names only q2. The engine's complete invariant suite accepts the state.

The reopening routine sets the old commitment only when the pointer is empty. Otherwise it opens the response/execution states without accounting for that second commitment.

### D2. Reopening during an unrelated review immediately fails I14

This sequence uses the normal duty rotation, not a manual roster edit:

| Tick | Event |
|---:|---|
| 29 | C approves A's first result; the window ends at 39. |
| 30 | Normal rotation puts A on duty and releases D. |
| 31 | D takes another ordinary task and A is assigned to review it. |
| 31 | B audits A's earlier result and returns ⊥. |

The reopening sets A's ordinary commitment to the old task while A still holds the unrelated open review:

```text
I14 A is committed and holds an open review
```

It also leaves A counted as on-duty while committed to ordinary work.

The idle-actor reopening control passes.

**Code:** `sim/engine.py:342–356, 398–415, 641–653, 1299–1322`; `sim/invariants.py:198–221`.

**Policy decision required:** If the actor has already taken another assignment, does reopened work wait, preempt, or follow some other explicitly bounded scheduling rule? What happens to its response clock and reserve membership? This review does not choose among those policies. It establishes that the current code has chosen no coherent one while still permitting execution or constructing a direct invariant violation.

Refusing an auditor's valid answer merely because the actor is busy would also need to be reconciled with the new reviewer contract; that is not suggested here as an automatic fix.

## E. A merged requester dispute and a reopening audit no longer ask one stable question

Rule basis: the inherited audit/dispute rule merges an in-progress audit into a paid requester dispute as one of its two reviews. v0.9 permits that same hidden audit role to answer P or ⊥. `ActorPolicy.review()` says a dispute asks for F/N with no objection disposition.

Reproduction:

1. C approves A's result.
2. D begins an audit.
3. H disputes the approval and pays the court fee.
4. E receives the other dispute-review assignment.
5. D returns P or ⊥ using its newly permitted fulfillment interface.

`_audit_reopens()` runs without considering `is_audit_as_appeal`. It changes the live case verdict, switches the actor into AWAITING_RESPONSE, and decrements the outstanding-item count from 1 to 0 even though the paid dispute still exists.

The concrete follow-on failures are:

| Auditor answer | Follow-on observation |
|---|---|
| P | E returns N; the orchestrator is allowed to resolve the split as N. Settlement decrements the count again, leaving `open_items=-1`. All eighteen invariants pass. |
| ⊥ | E's view still says `question="dispute"`, now with `appealed_assessment="⊥"`. E's documented F/N-only response is rejected unless it adds the objection disposition prescribed for a different question. |

The existing dispute with definitive audit F or N settles correctly in both controls.

**Code:** `sim/engine.py:494–506, 598–624, 641–653, 757–819, 851–880`; `sim/strategies.py:23–29`.

**Policy decision required:** When an audit already belongs to a paid dispute, how does its request for revision/evidence interact with that dispute, the remaining reviewer, the actor's right to appeal ⊥, and the single challenge round? The current code changes the question implicitly while preserving the older challenge container. The review does not choose a new merge policy; it requires a selected policy to be reflected in the admitted response contract and settlement.

## 4. Suggested disposition

The central new concept is **reopening an already approved case**. It interacts with several facts that were previously one-way: the approval's historical timestamp, the actor's released capacity, the identity of the assessor, and a review position's assignment lifecycle.

Most findings can be corrected without changing incentives, prices, bonds, or the preferred purpose. The capacity and merged-dispute intersections need explicit decisions, not just patches that happen to pass these fixtures.

I would keep v0.9's standing rule for scoped experiments. A declared root-only, F/N-only reviewer scope with actual human rulers and no post-settlement corrections avoids the reported reopening paths and remains a reasonable next experiment. This is a scoped recommendation, not general certification of all possible binary-action sequences, and no strategy experiment was conducted in this review.

For the full advertised interface, record these reopening combinations as not yet conformant. A timeout that cannot be replaced, an actor executing twice, a wrong liability target, or a mutable timestamp that invalidates earlier legal acts must not be interpreted as an economic consequence of participant strategies.
